# 福州轨道交通城市数据说明

## 数据来源

线路走向、站点坐标、站名（中英）与站型来自 CGo OpenMap 线路图在线编辑器导出的线路图工程；
站点经纬度登记在 `amap_data.json`，来源为高德地铁图接口
`https://map.amap.com/service/subway?srhdata=3501_drw_fuzhou.json`，坐标系 GCJ-02，
供地图卡片定位、里程兜底与「查找最近车站」使用。

首末班车（`data_timetable.js`）与车站出入口、空间示意图（`data_site_space.js`）来自
福州地铁官网「站点查询」`https://www.fzmtr.com/services/siteQuery`。

## 站间距说明

`data_lines.js` 的 `distances` 是**土建/地图口径**的站间里程：按 OpenStreetMap
（ODbL 1.0）各线 `route=subway` 关系的轨道几何沿线里程差分求得，取整到 10 米；
OSM 缺站台节点的车站改用高德 GCJ-02 站坐标转 WGS-84 后投影到该轨道几何求得。
它用于区间用时、里程显示与等时圈，**不代表计费里程**。

> ⚠️ **计价站距与土建站距不是同一套数**（本项目既定口径）：
> 计费里程由票制里程表口径决定，是收费依据；土建站距是按地图/轨道几何量出来的实际站间距。
> 两者在票价档位分界附近差 0.2~1.7 km 属正常现象 ——
> **不要为了让票价算得准而去改 `data_lines.js` 的 `distances`**，那会毁掉图上里程的真实性。
> 票价一律走官方票价表（见下节），不依赖站距推算。

## 票价：只取自官网抓取的官方票价表

`data_official_fare.js` 收录了福州地铁官网「票价线路查询」
`https://www.fzmtr.com/services/routeQuery` 背后的接口
`https://www.fzmtr.com/api/system/way/list?pageNum=1&pageSize=10&startStation={站名}&endStation={站名}`
给出的**全网 102 座运营车站两两组合的官方票价**（10302 组，双向齐备）。

`fuzhou.js` 的票价规则**只查这张表**，代码里不含任何按里程推算票价的公式：

- 表里有 → 直接返回官方价格；
- 表里没有 → 返回 `null`，内核按「票价未知」处理、**不显示票价**（不猜、不估）。
  会落到这一支的只有两种情况：起点或终点是官网未收录的 3 座未开通车站
  （莲花 / 壶井 / 滨海西），以及同站进出。

> 为什么不按里程算：**计价站距与土建站距本就不同源**（见上节），拿 `data_lines.js`
> 的地图站距去套计费规则，在票价档位分界附近必然错档 —— 实测约 3% 的站对会差 ±1~2 元。
> 官方票价表直接给出结论，不需要任何里程推算，也就不存在这个误差来源。

票制背景（仅供阅读，代码里未实现）：福州市发改委《关于滨海快线票价的通知》
（榕发改价格〔2025〕51 号）把滨海快线分成主城区段（福州火车站—帝封江，计价 13.91 km，
与地铁同网分段计价）与新区段（帝封江—文岭，计价 47.85 km，里程 × 0.3 元/公里、按元四舍五入），
跨段行程两段分别计价后累加，单次行程不低于 2 元。这些规则已由官方票价表逐对体现。

## 站间用时与站外换乘步行时间

区间用时由共享层（`city/shenyang/shared/route-data.js`）从 `data_timetable.js` 的首末班
逐站差值推算，**不是**按站距估算。福州全部 111 个区间都拿到了实测值（未开通站所在的少数
区间除外，走距离模型兜底）。已核对：各线「首班车全程用时」与「逐站差值之和」完全相等
（1/2/4/5 号线 53/53/52/48 分），故推算链路无系统性偏差 —— 精度上限取决于官网时刻表
本身只到分钟，单段差值即 ±1 分钟量级。

**站外换乘的步行时间**按站对单独配置（`fuzhou.js` 的 `walkMinutes`，逐对覆盖共享层的
6 分钟默认值；机制见 `shared/route-data.js`）：

| 站外换乘 | 步行时间 | 备注 |
| :--- | ---: | :--- |
| 水部（2 号线）⇄ 闽都（滨海快线） | **10 分钟** | 地面直线约 525 m，含进出站、过街与站厅穿行 |
| 三叉街（1 号线）⇄ 三叉街（滨海快线） | **6 分钟** | 地面直线约 406 m，两站分属不同付费区，须出站换乘 |

> 经地铁安检后即可换乘（见 2025-09 官方换乘指南），故两线共用同一车站 `M104`、

## 规划优先级：只有三种候选

行程规划给乘客的候选是 **时间最快 / 最少换乘 / 票价最低** 三种，**没有「距离最短」**。

理由：乘客实际更关心「少换乘」与「时间短」；最短距离在轨道交通里与观感关系不大，
而且**刻意追求最短距离常常反而更耗时** —— 直线走廊未必有直达车，多一次换乘就多几分钟。

> 这一项**已从内核整体移除**（不再作为 `OBJECTIVES` 的一个寻路目标），
> 所有城市一致，不再各城单独配置。原先福州用 `disabledObjectives: ["distance"]`
> 单独撤下，现该机制已一并删除，见 `shared/route-planner.js` 的 `OBJECTIVES`。
>
> 里程本身仍然保留：结果里的 `distance` 字段、等时圈的用时口径、按段计价线路的
> 结算都要用它，只是不再作为一种**寻路目标**。票价图的票价上限原先借「距离最短」
> 跑一遍全网，现在改用「耗时最远」那一对（实测两者结果一致，见 `extremes()`）。

## 未开通车站

滨海快线的**滨海西**、6 号线的**莲花 / 壶井**在图上以 `type: "no"` 呈现
（官网尚未收录这三站，故不在 `data_timetable.js` 与 `data_official_fare.js` 里）。
滨海西是**已经计入官方里程链**的中间站（官网「福州火车站→文岭」标注为 13 站），
保留它在站序里是必要的，不是多余节点。

## 自检

本目录的 `tools/` 下有两个**福州专属**的 Node 端核对脚本（零依赖、不需要浏览器、不联网）：

```bash
node city/fuzhou/tools/fuzhou_check.js           # 城市数据 ↔ 城市配置 契约
node city/fuzhou/tools/fuzhou_network_check.js   # 端到端：真建一次网络
```

- **`fuzhou_check.js`**（快，不依赖共享层）：车站引用完整性、站距长度、时刻链终点站解析、
  里程口径对照、官方票价表完整性与规则命中、「查不到必须返回 null」、站外换乘步行时间表、
  站内换乘方式表（键必须是真实换乘站、取值合法、`pairs` 覆盖自洽、帝封江三条线路对钉住），
  共 **51 项断言**。
- **`fuzhou_network_check.js`**（慢一点，会拉起共享层建图）：验证那些**只有内核读得懂**、
  写错了不会报错只会静默回落的配置 —— 逐对打印网络里实际的步行分钟数、逐站逐线路对
  （区分方向）打印换乘用时与方式、列出哪些区间来自时刻表实测、并抽样实算路径确认
  换乘方式进了结果步骤。

改动本目录任何数据或 `fuzhou.js` 后两个都请跑通；
`drunk/tools/selfcheck.js`（Drunk 纯函数层，跨城市通用）与本二者互补，互不替代。

重新抓取官方票价表所需的接口、参数、站点清单来源与并发建议，写在
`tools/fuzhou_check.js` 的文件头；抓完请同步递增 `sw.js` 的 `CACHE_NAME`。
