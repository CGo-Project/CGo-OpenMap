# 07 · 静态资源、加载与 Service Worker 缓存

> 本章回答资源从哪里引用、为什么可能缺失或显示旧版，以及更改代码后如何维护版本一致性。本文描述架构和检查方法，不规定某次提交的实际版本号。

## 1. 三条资源加载路径

1. **页面静态加载**：`main.html` 用 `<link>` / `<script>` 加载公共样式和公共能力模块，脚本按依赖顺序执行。
2. **城市脚本动态加载**：`main.html` 取得当前城市 `folder`/`id` 后，通过 `document.write()` 加载城市主脚本和基础数据；青岛 `qingdao.js` 继续用 `document.write()` 加载青岛专题数据及模块，并在 head 追加青岛 `style.css`。
3. **运行时资源请求**：SVG、图标、字体、地理坐标 JSON、地图瓦片等由页面或模块按需请求；缓存行为受浏览器和 Service Worker 共同影响。

维护时先辨认资源来自哪条路径：脚本不存在可能是加载顺序或文件路径问题；SVG 颜色不生效可能是 `<img>` 与内联 SVG 的区别；请求成功却显示旧资源可能与 SW 的缓存精确匹配有关。

## 2. 青岛资源清单和职责

| 资源类型 | 典型位置 | 使用方式与注意事项 |
|---|---|---|
| 海域 | `city/qingdao/assets/qingdao_sea.svg` | `data_scattered.js` 声明为散点；`qingdao.js` 将渲染后的 `<img>` 内联化，以支持主题 CSS 变量 |
| 交通图标 | `city/qingdao/assets/China_Railway.svg`、`Aircraft.svg`、`Long_Distance_Bus.svg`、`Ship.svg`、`Streetcar.svg` | 由散点数据引用；暗色主题滤镜在青岛 CSS 中 |
| 罗盘 | `city/qingdao/assets/compass.svg` | 由散点层定位，不负责地图变换 |
| 线路号徽标 | 公共 `assets/svg/` 资源 | `modules/qingdao_line_badges.js` 读取 `QINGDAO_MAP_LINE_BADGE_CONFIG` 定位与显示；不要只改 SVG 而忘记数据配置 |
| 站名检索 | `city/qingdao/staname.csv` | 属于搜索别名数据，不是页面脚本；需核对加载和解析逻辑 |
| 地理坐标 | `city/qingdao/amap_data.json` | 与主地图逻辑坐标不同，用于地理定位功能；名字重合时注意 station ID |
| 其他共享图标与字体 | `assets/` 及公共 CSS 中声明的路径 | 先找实际请求 URL、CSS `@font-face` 和使用方；保持路径大小写一致 |

SVG 坐标与图像内部 `viewBox` 是资源的局部坐标系。海域 SVG 具有 `viewBox=0 0 2700 2250` 及内部 `scale(0.9)`；替换素材前要核对散点中心、宽高、CSS 补绘起点和主题填色。

## 3. 青岛更新的强制版本检查

**每次修改青岛代码、CSS、数据并输出补丁时，必须递增根目录 `sw.js` 中的 `CACHE_NAME`**；这是每轮更新不可省略的检查项，不应留到提交 PR 时才处理。

青岛的加载链还需同步检查：

- `main.html` 中城市资源动态加载用的版本参数。
- `city/qingdao/qingdao.js` 中青岛资源版本参数（及由它加载的专题模块）。
- `sw.js` 的 `CACHE_NAME`。该缓存名称变更不等于浏览器会自动改写旧 `?v=` URL，故应同时核对资源实际请求地址。

准备提交 PR 前，提醒用户再次核对根目录相关入口页面（包括 `index.html`、`main.html`、`privacy.html` 等）中的资源版本号，确认是否需要整体同步。版本使用 `YYMMDD.HHMMSS` 格式，依据**真实更新时间**递增，不使用倒退或虚构的版本号。

**权限边界：**青岛目录外原则上只修改必要的资源版本字段；不为统一版本而触碰 Core 业务逻辑、其他城市代码或公共样式。项目通用缓存规范可能要求全站版本一致，但青岛独立维护阶段以用户明确批准的修改边界为先；如存在冲突，应先报告，不擅自调整其他城市。

## 4. Service Worker 的三种响应策略

| 请求类型 | `sw.js` 处理 | 维护影响 |
|---|---|---|
| 页面导航 (`navigate`/`document`) | Network-First：网络响应成功写缓存；断网时尝试缓存页面，最终回退 `./index.html` | HTML 更新通常优先取网络，离线可能仍显示缓存 |
| 同源静态资源（JS/CSS/图片等 GET） | 先查当前 CACHE_NAME 内精确请求（包含 query），未命中尝试网络并回填；网络失败时以 `ignoreSearch:true` 查缓存 | 相同 `?v=` 可能直接命中旧内容；更新 query 后才能触发新 URL 的网络请求 |
| 地图瓦片 (`autonavi.com`/`cartocdn.com`) | 使用独立 `map-tiles-cache`，缓存优先，未命中请求网络并缓存可接受的响应 | 瓦片不会随普通版本升级自动清除 |

其余跨域 GET 请求不经过上述同源静态缓存；非 GET 请求直接放行。

## 5. 安装、激活与预缓存

`ASSETS_TO_CACHE` 维护预缓存条目，包含页面外壳、编辑器、公共资产以及多个城市的数据文件。安装时 `precacheAll()` 分批执行，当前每批最多 2 项，批间隔 180ms；单项失败会记录警告而不会使全部安装中断。安装完成后 `skipWaiting()`；激活时删除不等于当前 `CACHE_NAME` 且不等于 `TILE_CACHE_NAME` 的旧缓存，随后 `clients.claim()`。

这个过程有两个容易误判的点：

- 预缓存清单是“尝试提前缓存”，不是全部请求成功的强保证；资源是否实际存在仍需检查 Network 和 Cache Storage。
- 文件数较多时，频繁连续改变版本会反复进行全量预缓存，可能给本地静态服务带来过量连接与文件句柄压力。更改缓存策略前应先理解 `sw.js` 中有关分批与错误处理的注释及现有功能边界。

## 6. 资源异常的排查顺序

### 6.1 修改 JS/CSS 后网页仍旧

1. 看浏览器实际加载的文件 URL（包括 `?v=`），不是只看本地文件名。
2. 对照 `main.html`、`qingdao.js`、`sw.js` 与缓存规范中的版本值。
3. 在开发者工具中区分 `from ServiceWorker`、内存缓存与直接网络响应。
4. 检查是否存在旧标签页仍由旧 SW 控制，以及相同请求 URL 的精确缓存命中。
5. 若文件请求本身失败，检查服务是否正常，而非首先认定 SW 有误。

### 6.2 图片/徽标/字体缺失

1. 查 DOM 的 `src/href` 或 CSS `url()` 实际路径，确认大小写、相对路径和 query。
2. 在 Network 核对 HTTP 状态、MIME、返回正文是否真是资源而非 HTML 回退。
3. 看数据是否引用正确的图标（例如 `QINGDAO_MAP_LINE_BADGE_CONFIG` 与徽标模块）。
4. SVG 区分外链 `<img>` 与内联 `<svg>`：外链通常不能继承主页面 CSS 变量，青岛海域有专门内联逻辑。
5. 字体还需确认 `@font-face` 指向的路径和可访问性；不要仅凭画面字体形状推断资源已加载。

### 6.3 离线异常

1. 核对页面是否通过 localhost/HTTP(S) 打开并处于允许注册 SW 的安全上下文（直接 `file://` 不同）。
2. 核对 `navigator.serviceWorker` 注册及激活状态、当前控制页面的 worker。
3. 核对资源是否实际存在于预缓存或运行时缓存，网络不可用时是否走到模糊匹配。
4. 区分地图瓦片缓存、页面外壳缓存和青岛 JS/CSS 缓存，不要一键清空当作定位结论。

## 7. 修改与验收清单

- [ ] 新增资源：确认文件路径、大小写、引用方、所需预缓存清单以及实际加载顺序。
- [ ] 城市 CSS：确认在 `qingdao.js` 加载后才使用；样式 scope 不扩散到其他城市。
- [ ] 模块脚本：确认数据依赖先于消费者加载，`StationBoard` 注册机制可用。
- [ ] SVG：验证亮暗主题、尺寸、viewBox、内联/外链语义、地图坐标。
- [ ] **每次青岛更新：`sw.js` 缓存版本必须递增**，并检查 `main.html`、青岛 `qingdao.js` 的实际资源版本与加载结果。
- [ ] **提交 PR 前：**提醒用户核对根目录入口页面的版本同步；未经许可不修改其他城市或 Core 业务代码。
- [ ] 在线与离线：分别验证正常网络、刷新、冷启动、资源请求失败时的行为。
- [ ] 浏览器和移动端：确认控制页面的 SW、CSS/JS 加载路径与交互正常。

本文只针对源码中可核实的策略作说明，实际缓存命中、安装成功率和视觉效果仍需浏览器验收。
