# CGo OpenMap - 地图全局物理尺度与站距等比伸缩操作指南与 AI 提示词规范

> **适用对象**：开源社区贡献者、新城市主理人、初学者开发者，以及驱动各类 AI Agent（DeepSeek-V3/R1、Antigravity、Claude Code、Cursor、Cline 等）的执行规范。  
> **核心目标**：针对新制图或移植线网中常见的“**全局尺度过小/车站极端拥挤叠字**”或“**全局尺度过大/线网稀疏空旷**”问题，提供一套入门级零门槛、仅需调节单个参数即可精确控制整张地图疏密程度的标准化 AI 提示词与工程实施方案。

---

## 1. 核心背景与实战范例（以「北京规划」线网重构为鉴）

在 CGo OpenMap 社区的实际开发过程中，许多新参加人员或城市移植者在初版线网生成时（尤其是基于真实经纬度 GIS 投影、位图矢量化或手绘初版数据导入后），最容易遭遇**全图物理尺度严重失衡**的困境：

### 🚨 典型痛点一：全局尺度过小 / 车站极端拥挤（北京规划线网重构前实况）
- **现象**：中心城区（如北京二环/三环、各市中心密集区）站与站之间的物理距离仅有 **15 ~ 28 像素**。
- **后果**：站名文字大面积骑跨在轨道线上、相邻中英文站名互相重叠打架成“黑块”，换乘图标被遮挡，全无视觉呼吸感。
- **实战重构范例**：在制作「北京规划」（`city/beijing_plan`）线网时，初版因为将远达 300 公里的张家口、承德、保定等城际端点站与市中心硬性线性映射，导致五环内站距被挤压到仅 20px 左右。项目组通过**全局物理坐标拉大 3 倍以上（非线性空间流线型展开）**，将中心城区站距均匀拉开到 **75px ~ 140px**，站名文字得以从容避让，彻底消除了全部文字叠字问题！

### 🚨 典型痛点二：全局尺度过大 / 线网松散空旷
- **现象**：相邻车站动辄间隔 **200 ~ 350 像素**，整张图大片死白/死黑空洞，线路被拉扯得无比冗长。
- **后果**：在手机端或初次打开网页时，必须极大程度缩小才能看到线网全貌，而缩小后文字与图标又变得极小无法辨识，破坏了轨道交通图的紧凑与节奏感。

## 2. 核心原理辨析：“物理间距等比伸缩” vs “单纯视口/SVG放大缩小”

> [!CAUTION]
> **初学者最容易陷入的误区：以为改改 `defaultScale` 或用浏览器缩放就能解决拥挤！**  
> 很多初学者遇到站名重叠时，第一反应是去改 `city/data.js` 里的 `defaultScale: 1.0` 调成 `defaultScale: 2.0`，或者让用户在浏览器中按 `Ctrl + 滚轮` 放大——**这是完全无效的！**

### ❌ 为什么单纯视口/SVG缩放（ViewBox Zoom）无法解决文字拥挤？
- 在 SVG 矢量渲染中，视口缩放属于**全要素几何线性放大**：
  - 车站图标尺寸（如 `10px` / `17.5px`）、中文字号（`12px`）、英文字号（`8.5px`）、轨道线宽（`8.15px`）与两站之间的相对间距是**同比例放大**的。
  - **数学证明**：假设两站原本相距 `20px`，文字宽度 `48px`，此时文字重叠溢出；若在视口放大 2 倍，虽然站间距在屏幕上变成了 `40px`，但原本 `12px` 的文字在屏幕上也变成了 `24px`（文字宽度随之翻倍为 `96px`）！**站间距与文字尺寸的相对比例毫无改变，文字依然 100% 重叠遮挡！**

### ✅ 什么是真正的“物理坐标等比伸缩”（真正的疏密调控）？
- **视觉要素尺寸绝对恒定**：车站图标半径（`dot 4.5px`/`tsf 17.5px`）、轨道线宽（`8.15px`）、中文字号（`12px`）、英文字号（`8.5px`）与 UI 控件大小**严格锁定不变**。
- **物理间距等比拉开 / 收拢**：
  - 将所有车站的物理坐标 $(x, y)$ 与所有线路的走向折点 `pathPoints` 等比放大或缩小（乘以缩放倍数 $K$）；
  - 画布尺寸 `mapSize` 与中枢 `center` 相应更新；
- **排版质变**：当站距从 `20px` 真实拉大到 `80px` 时，文字依然保持标准的 `12px`，此时每座车站周围凭空多出了 **60 像素的黄金呼吸空间**，所有叠字问题迎刃而解！

## 3. 入门参加者专用：AI 提示词模板库（直接复制给 AI）

你无需手动计算数百个车站的坐标，也无需编写脚本。只需将以下提示词中的 `【城市ID】` 和 `【缩放倍数】` 替换为你自己的需求，直接发给 **DeepSeek / Claude / Antigravity / ChatGPT**，AI 将自动为你完成全套文件的无损调整！

### 📋 模板 A（推荐 · 极简单参数版）：指定倍数快速伸缩全图间距

> **适用场景**：你刚做好了城市地图，但发现站名挤在一起（需要拉大间距），或者站与站离得太远（需要收缩间距）。  
> **复制以下内容发送给 AI：**
>
> ```text
> 你好！我正在为城市【城市ID，例如 shanghai】制作轨道交通线路图。
> 预览时我发现整张地图的车站间距【太挤了有叠字 / 太空旷了线条过长】。
> 请参考 docs/GLOBAL_SCALE_PROMPT.md 规范，帮我将该城市的全局车站与线路物理间距等比缩放为原来的【缩放倍数，例如 1.5 倍拉开 / 0.8 倍收拢】：
> 
> 核心要求与技术红线：
> 1. 这是物理坐标等比伸缩，不是单纯调整 defaultScale 或视口缩放！车站图标尺寸、文字字号、轨道线宽严格保持原生标准大小；
> 2. 读取 city/【城市ID】/data_stations.js，将所有车站的顶层物理坐标 (x, y) 乘以【缩放倍数】，四舍五入保留1位小数；
>    【严禁修改】车站内用于微调站名的 offset: { x, y } 偏移量和 textScale，它们必须逐字节原样保留！
> 3. 读取 city/【城市ID】/data_lines.js，将所有走向折点（pathPoints、pathPoints-main、pathPoints-branch*）中的坐标 (x, y) 以及圆角半径 r（若有）同步乘以【缩放倍数】；
> 4. 若存在 data_notopen.js 或 data_scattered.js，其中的折线点阵亦同步缩放；
> 5. 读取 city/data.js，将该城市的 mapSize.width、mapSize.height 以及视口中心 center.x、center.y 同步乘以【缩放倍数】；
> 6. 更新 sw.js 顶部的 CACHE_NAME 缓存版本号（按 yymmdd.hhmmss 格式）；
> 7. 修改完成后，在本地运行 node editor/tests/selfcheck.js 验证回归测试 100% 通过。
> ```

---

### 📋 模板 B（直观站距版）：指定目标核心区站距自适应求解

> **适用场景**：你不确定到底该缩放到 1.3 倍还是 1.8 倍，只知道“希望市中心站与站之间大约相隔 80 像素”。  
> **复制以下内容发送给 AI：**
>
> ```text
> 你好！我想优化【城市ID，例如 shenzhen】地图的排版疏密程度。
> 请阅读 docs/GLOBAL_SCALE_PROMPT.md：
> 1. 请先检查 city/【城市ID】/data_stations.js 中核心密集区相邻车站的平均像素间距当前约为多少；
> 2. 我期望将核心区的平均站间距调整为约【期望像素站距，建议 75~100px】左右；
> 3. 请帮我自动计算出所需的最佳缩放倍数 scaleFactor，并按规范等比缩放 data_stations.js、data_lines.js、city/data.js 中的全部物理坐标；
> 4. 严禁改动 offset 文字微调量，保持所有图标尺寸不变，并更新 sw.js 缓存版本号。
> ```

---

### 📋 模板 C（规划线网高阶版）：Asinh 非线性径向拉伸（对标北京规划）

> **适用场景**：超大型综合规划网（包含市中心密集地铁 + 外围超远高铁/市郊客运干线，如延庆、怀柔、张家口、保定、雄安同图呈现）。若简单线性放大，外围长途线会使画布暴增至数万像素。  
> **复制以下内容发送给 AI：**
>
> ```text
> 你好！我的【城市ID】线网中同时包含了市中心超高密度地铁与远郊超远距离城际高铁。
> 如果简单按线性放大，外围车站会导致画布尺寸失控。
> 请参考 city/beijing_plan/scratch/build_beijing_plan.js 中的 Asinh（反双曲正弦）非线性展开算法：
> 1. 以市中心中心点 (cx, cy) 为径向锚点；
> 2. 在核心城区（半径 r < r0 区域）应用较大的比例系数 S0（使市区密集站距达到 75~120px）；
> 3. 对外围远距离车站通过 R = S0 * r0 * asinh(r / r0) 自然平滑收敛，防止长距离端点站过度外扩；
> 4. 重新计算并回写全网车站与线路折点，完成画布与缓存同步。
> ```

## 4. AI Agent 执行技术规范与铁律（防止数据损毁）

所有执行全局尺度调整任务的 AI Agent，必须严格遵循以下**七大执行铁律**：

| 步骤 | 目标文件 | 执行操作与核心规则 | 严禁行为 |
| :--- | :--- | :--- | :--- |
| **1. 车站数据** | `city/{city_id}/data_stations.js` | 遍历 `stationsData`，将 `station.x` 与 `station.y` 乘以 $K$（保留 1 位小数）。 | 🚨 **绝对严禁修改 `offset: { x, y }`**！`offset` 是文本相对车站圆点的相对偏移（如 4px），放大它会导致文字脱离图标飞出！ |
| **2. 线路走向** | `city/{city_id}/data_lines.js` | 缩放 `pathPoints`、`pathPoints-main`、`pathPoints-branch1/2` 等全部走向折点的 `(x, y)` 与倒角半径 `r`。 | 🚨 绝对严禁改动 `distances` 运营里程（米制真实里程不随地图排版变化）！ |
| **3. 未开通线** | `city/{city_id}/data_notopen.js` | 缩放在建虚线走向数组 `points` 中的所有 `(x, y)`。 | 严禁遗漏在建线走向，否则在建虚线会与既有线网脱节。 |
| **4. 画布视口** | `city/data.js` | 将目标城市的 `mapSize.width`、`mapSize.height` 与 `center.x`、`center.y` 同步乘以 $K$ 取整。 | 严禁只改站点不改画布，否则会导致车站越界飞出视口边界。 |
| **5. 零损回写** | 全量修改文件 | 保留原有注释、中英文站名、`type`、`align`、`company` 等所有元数据。 | 严禁通过 `JSON.stringify` 粗暴抹除人工编写的代码注释。 |
| **6. 缓存升级** | `sw.js` | 将顶部的 `CACHE_NAME` 递增为严格 12 位纯数字带小数点（`cgo-openmap-v{yymmdd.hhmmss}`）。 | 🚨 严禁漏更 `sw.js`，否则强缓存会导致所有缩放修改在浏览器中完全不起作用！ |
| **7. 自动化校验** | `editor/tests/selfcheck.js` | 在终端运行 `node editor/tests/selfcheck.js`。 | 必须 100% 通过全部回归断言，若有单项失败须立即排查修复。 |

## 5. 项目内置开箱即用命令行工具 (`scripts/rescale-city.js`)

为了让初学者和 AI Agent 能够一秒完成全局缩放，本项目已在根目录内置了经过全面回归断言验证的零依赖 CLI 工具：

### 命令语法：
```bash
node scripts/rescale-city.js <city_id> <scaleFactor> [--dry-run]
```

### 参数说明：
- `city_id`：已在 `city/data.js` 中注册的城市唯一英文标识（如 `shanghai`、`beijing`、`beijing_plan`、`shenzhen` 等）；
- `scaleFactor`：间距缩放倍数（浮点数，如 `1.5`、`0.8`、`2.2`）；
- `--dry-run`（可选）：仅执行空间计算并输出前后对比统计，不修改任何磁盘文件。

### 实战示例：
```bash
# 1. 模拟预览：将北京规划线网站间距整体拉大 1.5 倍（不实际写盘）
node scripts/rescale-city.js beijing_plan 1.5 --dry-run

# 2. 正式执行：站间距拉大 1.5 倍，自动写回 data_stations.js、data_lines.js、city/data.js 并更新 sw.js 缓存
node scripts/rescale-city.js beijing_plan 1.5

# 3. 紧凑排版：将上海线网站间距整体收拢 20%（消除过大空白）
node scripts/rescale-city.js shanghai 0.8
```

## 6. 缩放完成后的排版验收清单 (Checklist)

执行完全局物理尺度缩放后，请对照 [《线路图质量评定规范》(docs/QUALITY_STANDARDS.md)](./QUALITY_STANDARDS.md) 快速核查以下 5 项：

- [ ] **1. 文字零重叠**：市区密集区域站名中英文互不重叠，中文字体（12px）到相邻轨道线保持至少 4px 呼吸间隙。
- [ ] **2. 车站与文字不脱节**：站名依然稳固贴合在车站圆点旁边（确认 `offset` 未被误放大）。
- [ ] **3. 线路平滑连续**：拐角倒角平滑自然，无折点错位或线网破裂悬空。
- [ ] **4. 视口默认居中**：打开网页时，镜头依然准确对准城市核心枢纽（如人民广场、天安门、市民中心）。
- [ ] **5. 全图缩放可读**：在浏览器中适度缩小全图，各干线走势依然清晰，大图空间利用率饱满。
