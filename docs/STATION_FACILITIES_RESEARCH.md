# 车站设施信息：前期调研

> 调研时间：2026-09-30　状态：**仅调研，未实施**
>
> 起因：上游 CentralGo（`centralgo.site/map`）上线了「出入口与设施」功能。本文核对
> 沈阳地铁官网的数据可得性，判断本项目（纯静态、零构建）能否跟进、以及跟进什么。

## 一、结论摘要

1. **设施数据值得做，且成本比预期低**。沈阳地铁官网对**全部 159 座运营站**都刊载了
   设施文字，字段规整（9 类设施 + "楼层 + 相对位置"文案），且有现成的 JSON 接口。
2. **出入口数据相反，不建议做**。官网**没有**出入口的方位、描述与坐标，层级图上的
   出入口只有字母方块。要做出入口就得另找来源（OSM 是候选）并自行采集坐标，
   工作量比设施大一个数量级。
3. **纯静态站的唯一障碍是取数方式**：接口是 **POST、无静态 JSON 文件**，因此不能在
   构建时"拉一下就完事"，需要在离线/开发阶段抓取一次落盘成静态数据。
4. **ID 映射这一环已经有现成的**：`data_timetable.js` 的 `SYMTC_OFFICIAL_STATION_ID_RULES`
   已把本地车站 ID 映射到官网编号，层级图卡片正是在用这套映射。

## 二、官网的设施数据（本次调研的核心发现）

### 2.1 接口

同源、**POST**、`Content-Type: application/json`、**无 token、无验证码**：

| 接口 | 请求体 | 用途 |
|---|---|---|
| `/portalManager/selectLineInfoByDC` | 无 | 线路清单（含线路色） |
| `/portalManager/selectStationInfoByDC` | `{"lineId":"00"}` | 车站清单（含经纬度、地址） |
| `/portalManager/selectDeviceInfoByDC` | `{"line_id":"00","station_id":"0000","device_id":"00"}` | **设施清单** |
| `/portalManager/selectTrainTimeTableInfoByDC` | `{"line_id":..,"trip_drct_cd":"00","stat_station_nme":..}` | 首末班车 |

响应统一为 `{ success, message, code, result: [...] }`。

### 2.2 设施记录的字段与样例

`selectDeviceInfoByDC` 的 `result` 是**扁平数组**，每站每设施一行：

```json
{"lineId":"02","stationId":"0217","stationName":"金融中心","deviceId":"03",
 "deviceDesc":"卫生间","deviceLocationDesc":"站厅层  无;站台层  开往桃仙机场方向车尾位置"}
```

- `deviceId` / `deviceDesc`：设施类别
- `deviceLocationDesc`：**楼层 + 相对位置**，多处以 `;` 分隔

### 2.3 设施类别（全套 9 类）

| deviceId | deviceDesc | 有有效位置文字的站数 |
|---|---|---|
| 01 | 乘客服务中心 | 159 / 159 |
| 02 | 自动售票机 | 159 / 159 |
| 03 | 卫生间 | 159 / 159 |
| 04 | 无障碍卫生间 | 159 / 159 |
| 05 | 母婴室 | 67 / 159 |
| 06 | 无障碍电梯 | 159 / 159 |
| 07 | 自动扶梯（上行） | 159 / 159 |
| 08 | 自动扶梯（下行） | 140 / 159 |
| 09 | 盛京通网点 | 14 / 159 |

注意：官网**没有** AED、没有"直梯"这一叫法（直梯并入"无障碍电梯"）。

### 2.4 位置文案的真实形态（逐字抄录）

```
沈阳北站
  乘客服务中心     站厅层 站厅中部位置
  自动售票机       站厅层 A出入口附近 ; 站厅层 B出入口附近
  卫生间           地下一层 A出入口附近 ; 站台层 开往桃仙机场方向车尾位置
  无障碍卫生间     地下一层 A出入口附近 ; 站台层 开往桃仙机场方向车尾位置
  母婴室           地下一层 A出入口附近
  无障碍电梯       地面-站厅 B出入口附近 ; 站厅-站台 站厅中部位置
  自动扶梯（上行）  地下一层 A、B出入口 ; 站厅层 站厅两端位置附近 ; 站台层 站台两端位置附近
  自动扶梯（下行）  地面层 A、B出入口 ; 地下一层 地下一层两端位置附近 ; 站厅层 站厅两端位置附近
  盛京通网点       站厅层 B出入口附近

中街
  乘客服务中心     站厅层 站厅AB出入口附近
  卫生间           站台层 开往双马方向车头位置
  无障碍电梯       地面-站厅 B1出入口附近 ; 站厅-站台 站厅中部位置

甘官（3 号线）
  卫生间           站厅层 站厅A、D口附近 ; 站台层 站台开往李达方向尾端
  母婴室           站厅层 站厅A、D口附近 ; 站台层 站台开往李达方向尾端

太原街（1/4 换乘，出现换乘通道写法）
  无障碍电梯       地面-站厅 站厅层F出入口附近 ; 站厅-站台 站厅付费区内E出入口附近 ;
                   站厅层换乘通道 1换4通道电扶梯附近
```

可归纳的文案特征：

- **楼层词**：`地面层 / 地面-站厅 / 站厅层 / 地下一层 / 站厅-站台 / 站台层 / 站厅层换乘通道`
- **方位词**：`附近 / 位置附近 / 中部 / 两端 / 车头位置 / 车尾位置 / 尾端`，以及`付费区内`
- **站台层带行车方向**：`开往桃仙机场方向车尾位置` —— 本项目已有 `loop-direction.js`
  与"报站目的地"机制，语义上对得上
- **自由文本**：同一含义有多种写法（`附近` / `位置附近`；`厅A、D口` / `站厅A、D口`），
  不宜强行结构化，按原文展示更稳

### 2.5 渲染端已做的清洗（照抄口径）

- 过滤掉 `deviceLocationDesc` 为空或等于 `"无"` 的条目；
- 按 `deviceId` 升序；
- 每条按 `;` 拆行显示；
- 含「暂停」字样的整段隐藏；
- 去掉「（投入使用）」字样；
- 图标取 `/wwmhm/icons//station_device_{deviceId}.svg`（`deviceId=9` 为 `.png`）。

### 2.6 覆盖度（全量实测，非抽样）

- 运营车站 **159** 座（线路：1、2、3、4、9、10 号线）；
- 设施记录 **1431** 条 = 159 × 9，**每站固定 9 条**；
- **设施文字覆盖率 159 / 159**（每站至少含乘客服务中心、自动售票机、卫生间、
  无障碍卫生间、无障碍电梯的文字）；
- **层级图覆盖率 159 / 159**。

## 三、副产品：接口里还有这些

- **每站经纬度**：`selectStationInfoByDC` 的 `onlineX`（经度）/ `onlineY`（纬度），
  十进制度字符串。例：沈阳北站 `123.435951, 41.817299`。
  注意 **3 号线部分站（凌空—方家栏段）为 `"0","0"`**，不可直接使用。
- **每站文字地址**：同接口的 `location`，形如`位于中街路与朝阳街交汇处`
  —— 即本项目 `stacard/data.js` 里 `location` 字段的来源，两处应保持一致。
- **线路色**：`selectLineInfoByDC` 的 `lineColor`（1号线 `#cf3517`、2号线 `#ee782d`、
  3号线 `#e668a0`、4号线 `#6f3d94`、9号线 `#008dd0`、10号线 `#80b72e`）。
- 官网**页面上不展示坐标**，坐标只存在于接口响应里。

## 四、车站层级图（本项目已在用）

- 本项目已通过 `shenyang_level_map.js` 热链官网层级图，挂在「车站信息」页签置顶。
- 图片地址：移动版 `/wwmhm/icons//czcjt/{官网编号}.png`（`icons` 与 `czcjt` 之间
  的双斜杠是官网自身写法，不可"修正"）；桌面版为单斜杠 `/ckfw/icons/czcjt/{id}.png`。
- 图片体积 **107 KB ~ 519 KB / 站**，159 站合计 **约 30 MB 量级**。
- **图上没有中文设施名**，只有设施图标 + 右侧中英文图例（乘客服务中心 / 自动售票 /
  自动扶梯 / 楼梯 / 出口 / 无障碍电梯 / 卫生间 / 无障碍卫生间 / 母婴室）。
  → 所以层级图**不能替代**结构化设施数据：它能"看"，不能"查"。

## 五、ID 映射（已有，不必新建）

- 官网编号 = **2 位线路号 + 2 位站序**，站序**步长为 2**，且是**线路内序号**，
  与全网红线无关；线路内还存在跳号（如 2 号线 `0271` 之后直接跳 `0203`），
  因此**不能靠"上一站 +2"盲推**。
- 本项目 `data_timetable.js` 的 `SYMTC_OFFICIAL_STATION_ID_RULES` 已覆盖
  1 / 2 / 3 / 4 / 9 / 10 号线的映射规则，并被层级图卡片实际使用 —— 设施数据可**复用同一套**。
- 有轨电车、国铁、未纳入官网编号体系的在建站没有官网编号，按「无数据不渲染」处理。

## 六、与上游 CentralGo 的对照

上游的设施模型是**独立数组**，字段为
`{ name{zh,en}, type, source, location{zh}, device_location }`，且**只有文字方位、没有坐标**
（坐标只挂在出入口的 `geo` 上，`facilities` 不参与地图落点）。

| 官网 deviceDesc | 可对到上游的 type |
|---|---|
| 卫生间 | `toilet` |
| 无障碍卫生间 | `accessible_toilet` |
| 母婴室 | `nursing_room` |
| 无障碍电梯 | `elevator` |
| 自动扶梯（上行 / 下行） | 上游把扶梯放在**出入口**的 `accessibility.escalator` 上，而非 `facilities` |
| 乘客服务中心 / 自动售票机 / 盛京通网点 | 上游**无对应**（属运营服务，非"设施"） |

**结论**：若将来要与上游对齐，采用 `facilities[]` + `{name, type, location}` 的形状即可；
但**上游的口径比官网窄**（没有乘客服务中心、售票机、盛京通网点），本项目不必削足适履 ——
按官网 9 类如实呈现更完整，同时保留 `type` 字段以便日后映射。

## 七、落地路径（供决策，尚未实施）

1. **离线抓取**：开发阶段跑一次脚本，POST 上面 2 个接口（车站 + 设施），
   落成 `city/shenyang/data_facilities.js`（静态常量，与 `data_timetable.js` 同风格）。
2. **ID 映射**：复用 `SYMTC_OFFICIAL_STATION_ID_RULES` 推导官网编号 → 本地车站 ID。
3. **渲染**：仿 `shenyang_service_info.js` 里「出入口」那一行的做法，在「车站信息」
   页签增加一块设施列表；图标用 CGoUI 内置图标（不新增热链依赖）。
4. **清洗**：照 2.5 的口径过滤 `"无"`、去「（投入使用）」、隐藏含「暂停」的段。

**不建议做的事**：

- 不要把层级图下载进仓库（约 30 MB）；
- 不要把设施文字"结构化"成枚举（原文是自由文本，强转会失真）；
- 不要试图从官网取出入口坐标 —— 官网没有。

## 八、未决问题

1. **跨域**：官网接口是否允许本项目页面直连（CORS / Referer 校验）**尚未实测**。
   若允许，可省掉落盘；若不允许，走离线抓取。
2. **抓取频率与礼貌**：159 站 × 1 次即可，无需轮询；落盘后与官网可能长期不一致，
   需要约定一个"手动更新"的节奏。
3. **署名与合规**：数据来自沈阳地铁官网，展示时应注明来源；不可声称"官方数据"，
   自行采集的结论须标注待核验。
4. **出入口**：若日后确要做，候选来源是 OSM（`railway=subway_entrance`，ODbL 开放、
   自带经纬度，上游亦以其为主要来源），但**覆盖度尚未核查**。
5. **本项目的定位取舍**：沈阳一侧现有重心是"文化"（题字、文化墙、报站目的地），
   设施属纯功能信息，是否纳入需与城市主理人的编辑方针一致。
